# Submission guide (read first)

This archive includes the project source, core documentation, role instructions, and issue-body drafts.

It does **not** create a GitHub repository or genuine GitHub Issues. You must push it to your GitHub account and create issues so the real issue timestamps/comments are recorded. Never claim QA PASS until you have actually run tests and observed the output.

Recommended sequence:
1. Review `_docs/plan.md`.
2. Review the initial brainstorming record in `_docs/chat-brainstorm.md` and add the actual conversation turns required by your instructor.
3. Review the technology choice and backlog.
4. Push to a public GitHub repository.
5. Create the 9 proposed GitHub Issues from `_docs/github-issues/`.
6. Groom and process issues one by one following `_docs/process.md`.
7. Run setup, migration, `python manage.py check`, and `pytest`.
8. Submit the real repository URL before the deadline.
